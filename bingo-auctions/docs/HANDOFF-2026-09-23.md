## 5. Facts a new session would get wrong

1. **Shared station login.** Floor phones sign in as `bingoauctions.jared@gmail.com` (the `operator_users` station account). The worker is identified by PIN (`packages/db/migrations/0281_workers_pin.sql`); `app_feedback.reporter_label` = the PIN worker. `author_id` names the account, not the person or phone. Tell phones apart by `device_model` (Jared's canary: SM-S911U, Android 16; floor phone: SM-G998U, Android 14).
2. **Staff iPhones read the production channel.** They run TestFlight build #36 (09-10, `production` profile, eas-build run 34533638995). Its built-in id `57235432-…` is the only one iPhones reported from 09-11. The header of `eas-update.yml` ("TestFlight = preview") is **stale**. **Android floor phones read preview** (SM-G998U loaded 01a0cf4b from preview). An Android phone still reported `098adf06-…` at 13:23, meaning it hadn't restarted twice yet. Telemetry has no channel column, so this comes from timing.
3. **OTAs failed for a month.** `eas update` ignores `eas.json` `build.*.env`, so every OTA until 09-22 had no Supabase URL/key, threw at import, and silently rolled back. #365 loads the env in each publish step. `republish` refuses if source and destination envs differ.
4. **Deploy window.** Warehouse closes 18:00, but **18:00–21:00 is customer peak** (bids). The quiet window is **05:00–07:00 CDT**. CLAUDE.md Rule 9 still says only "closes at 6 PM" and hasn't been updated.
5. **Migrations.** Review JSONs (`packages/db/migration-reviews/*.sql.json`) are **convention, not enforced**. #359 reverted the runner check (see that README). What's enforced (CI only): `scripts/check-new-lot-migrations.cjs` (#360) requires a new destructive lot migration to call `assert_no_physical_footprint(uuid[])` on the captured IDs in the same transaction. The runner wraps each file in a transaction, so `CREATE INDEX CONCURRENTLY` is impossible and index builds block writes.
6. **Merging.** `gh pr merge` is denied for Claude **(confirmed by user 09-23)**. The user merges from their own terminal.
7. **No branch protection on master** (`gh api …/branches/master` → `protected: false`). Every CI guard is advisory; a red check doesn't block a merge.
8. **OTA mechanics.** A republish creates **new update IDs**, so watch for the IDs in the run log, not the source's. A device needs two launches to run a new OTA (download, then apply). Production has no per-device targeting; `--rollout-percentage` picks random devices.
