```
name: Worktree isolation is dangerous for parallel write-agents on shared branches
type: feedback

When dispatching multiple agents to write code in parallel against the auction-platform
repo, worktree isolation creates a hazard: each worktree branches off the same base
commit, and concurrent commits to the same branch produce merge conflicts, duplicate
migrations, and silently-incompatible code.

Pairs with feedback_check_wip_before_worktree.md (which covers the case of
uncommitted WIP being missed by worktrees).

How to apply:
1. Read-only audit agents → safe to parallelize with worktree isolation.
2. Write-agents on independent surfaces (e.g. one editing apps/bidder-app, another
   editing operator-web, another editing packages/db with no migration overlap) →
   acceptable to parallelize IF you explicitly plan the file-set per agent and the
   migrations don't collide.
3. Write-agents that may touch overlapping files (typical refactor/audit-fix sweep) →
   DO NOT parallelize with worktrees. Either:
   - dispatch a single agent that internally decomposes the work, OR
   - dispatch agents on explicit named feature branches, then coordinate merges
     manually after each completes.
4. Migration files (packages/db/migrations/NNNN_*) MUST be coordinated centrally —
   parallel agents will collide on the next sequence number unless given explicit
   non-overlapping slots in their prompts.

Specifically prevents:
- Two agents both writing 0127_*.sql against base 0126.
- Two agents both editing the same TSX component in conflicting ways.
- Re-running tonight's collision incident.
```
