## Pitfalls
- Persistent context on Windows: one profile dir = one running browser. A crashed or killed process leaves `SingletonLock` / `lockfile` behind and the next launch fails or shows a "profile corrupted" dialog (issue 35466). Own the lifecycle: one `BrowserSession` per person, `close()` in `finally`, stale-lock cleanup only when no PID is alive, and never point at Chrome's own `User Data` directory. Pass an absolute `user_data_dir` (relative paths resolve against the driver, issue 34700). Keep the path short and ASCII: `~/.oasis/drawers/<person>/browser-profile/`.
- Route interception misses things: (a) redirect hops are not routed ("working as designed", issue 34994) so a 302 from an allowed host to a blocked one passes the route gate; (b) requests served by a Service Worker are invisible unless `service_workers="block"`; (c) WebSockets need `route_web_socket`; (d) enabling routing disables the HTTP cache. Defence in depth: pre-check the host before `goto`, `context.route("**/*")` abort as backstop, `--host-resolver-rules=MAP <host> ~NOTFOUND` for every blocked host at launch (DNS-level, covers workers and redirects), and a `framenavigated` / response-URL re-check that bounces to `about:blank` and logs.
- Credential heuristics fail in both directions: a "show password" toggle turns `type=password` into `type=text` (track `hasBeenTypePassword` on first sight); OTP boxes are often six `type=tel|text` inputs with `inputmode=numeric maxlength=1` and no autocomplete; card fields live inside payment iframes (Stripe, Adyen) so the main-frame DOM never sees them; `autocomplete=off` is common on bank logins. Decide per field from type + autocomplete + name/id/label/aria/placeholder regex, in every frame, and refuse when any signal fires. Treat page text as untrusted: a label saying "not a password" does not unlock anything.
- Screenshots are PII by default. Mask credential-shaped locators with `mask=`, screenshot the viewport, not `full_page` (a long page is tens of MB and holds every table on it), prefer `type="jpeg", quality=60` for the trail, and route both the bytes and the `{step, host, path, ts}` metadata through `remote.scrubber` before any write. Playwright's own `record_video`/`tracing` write raw files to disk and bypass the scrubber: leave them off in production.
- macOS headed vs headless: a headed Chromium steals focus on every `new_page` and shows the dock icon; the default headless shell is a different binary, so some sites render or block differently. Use `channel="chromium"` (new headless, same binary) for unattended steps and headed only when the person must look (the submit ask). Issue 35466 reports a headless run failing to read cookies a headed run saved in the same profile; do not mix modes on one profile without a test that proves the session survives.
- Python event loop: agent-core is async, so use the async API; the sync API raises inside a running loop. On Windows the loop must be the Proactor one (Playwright spawns a driver subprocess); never set `WindowsSelectorEventLoopPolicy`.
- CI: `playwright install chromium` in the Windows job is slow (cache `%LOCALAPPDATA%\ms-playwright`); keep unit tests browser-free and the smoke tier opt-in.

## Recommended shape
1. `src/anorak/browser/port.py`: `BrowserPort` Protocol (`goto`, `fill`, `click`, `screenshot`, `current_url`, `frames`) and `FakeBrowser` for tests (records calls, serves canned DOM dicts and PNG bytes, fakes redirects).
2. `src/anorak/browser/playwright_port.py`: the only Playwright import; `launch_persistent_context` per person, `service_workers="block"`, `--host-resolver-rules`, `context.route` backstop, `add_init_script` that tags secret fields and hooks `submit`/`requestSubmit`/`click` on submit buttons to raise a `submit_intent` event.
3. `src/anorak/browser/hosts.py`: `HostPolicy(never_automate_hosts)` with tldextract registrable-domain match and IP literals; one `check(url)` used before goto, in the route handler and after navigation.
4. `src/anorak/browser/fields.py`: `classify(field_attrs) -> Credential | Plain` from type + autocomplete + regex (Chromium keys above); pure function, table-tested.
5. `src/anorak/browser/gates.py`: new-host ask and submit ask built on `ask_first.py`; submit is `always_ask`; a `credential` classification raises `CredentialRefused` with the plain-words line.
6. `src/anorak/browser/trail.py`: `ScreenshotTrail(scrubber)` is the only writer; it masks credential locators, scrubs metadata, writes `<step>.jpg` + `<step>.json`.
7. `src/anorak/browser/tool.py`: the `browser` chat tool wiring port + policy + gates + trail + ledger log line per action.
8. Tests: `FakeBrowser` drives every gate and the four mutation checks; `-m browser_smoke` runs `pytest-playwright` + `pytest-httpserver` against a local fixture page on macOS and Windows.
9. T92 imports `BrowserPort` and `HostPolicy` only, never Playwright.
10. `profile.yaml` gains `never_automate_hosts` (already named in T91); no new config format.
