# Connectors + rag-pipeline + remote — open-source options (2026-09-25)

Covers Graph/Google connector libraries with OAuth+refresh, MCP servers for the same services, doc ingestion/chunking, local embeddings/vector stores, PII/secret scrubbing, and OS-keychain storage. No unified-inbox OSS exists (Nylas/Unipile are closed SaaS) — closest real option is O365 + google-api-python-client behind our own thin adapter. No OSS library does "retrieval with a role gate" out of the box either; it's a metadata-filter pattern on top of a normal vector store (noted in the picks below), not a separate dependency.

## rejected

- **Nylas / Unipile** (unified inbox SaaS) — closed-source commercial APIs, not OSS; no license to verify, so never a pick regardless of fit.
- **GongRzhe/Gmail-MCP-Server** — MIT but no commit since Aug 2025 (unmaintained); also TypeScript/JS, not Python; several unaudited forks exist instead of one maintained project.
- **scrubadub** — Apache-2.0 but no commit since Sep 2023, well past the 12-month bar; Presidio covers the same ground and is active.
- **elyxlz/microsoft-mcp** (and its forks itsbrex/microsoft-mcp, robin-collins/m365-mcp) — no LICENSE file present, near-zero stars, no real adoption.
- **Unstructured-IO/unstructured** — Apache-2.0 (passes the gate) but heavy dependency tree and the project increasingly steers users toward its paid Enterprise platform; markitdown + docling cover the same PDF/Office parsing need more lightly.
- **LangChain / LlamaIndex** — MIT (passes the gate) but both are giant general-purpose frameworks; only worth borrowing a specific loader/splitter pattern from, not adopting as a dependency, per the brief's "small and focused over giant frameworks" preference.
- **Python Microsoft-Graph MCP servers generally** (nitin27may/ms-graph-mcp, timfurlong/msgraph-mcp, eesb99/msgraph-mcp) — each under 5 stars, effectively unproven; Softeria/ms-365-mcp-server is the one with real traction (995★, MIT, active) but it's TypeScript. This category just isn't mature in Python yet — don't adopt any as a dependency.
- **deepset-ai/haystack** — Apache-2.0 (passes the gate) but a giant RAG framework; its role-based metadata-filter retrieval pattern is worth reading, the framework itself is not worth adopting for a company this size.

## top 3

1. **python-o365 + MSAL** — fastest real path to T11's Outlook/OneDrive/Teams connect flow with token refresh already solved; just redirect its token cache into the T02 secrets interface.
2. **detect-secrets' entropy/keyword plugins + Presidio's PII operators** — together they cover almost exactly T04's scrubber spec (entropy ≥16-char strings, key-name regex, plus real PII beyond secrets) without writing that logic from scratch.
3. **markitdown → chonkie → fastembed → sqlite-vec** — a small, local-first, no-server ingestion→chunk→embed→store chain for the Phase 3 rag-pipeline that matches "small company," with docling as the escalation for table-heavy documents.
