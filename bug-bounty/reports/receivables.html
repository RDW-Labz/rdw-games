5 · Two corrections made today, before anything was filed on them

(a) karwei is not a takeover. The ≤$5,500 line in the previous edition was wrong. karwei.netlify.app does not 404 — it serves Karwei's own audiotour site, which means the Netlify site belongs to them and nobody, including us, can claim it. What is missing is only the custom-domain binding for www.audiotour.karwei.nl: a misconfiguration with no attacker in the loop. It is withdrawn from the offer list; filing it would have been an informative at best and a credibility loss at triage.

(b) The scope gate was lying, and the database was repaired. Apex detection used the last two labels, so www.cbn.com.bo was stored under a domain called com.bo and inherited an unrelated Visa asset's tier. Replaced with the Public Suffix List: 44 bogus apex rows removed, 73,390 hosts re-parented, 928 scope apexes corrected. Matching is now exact-asset or a wildcard the host sits under, with explicit exclusions winning — which takes the YesWeHack channel from ten hosts to zero, avoiding ten out-of-scope filings.

6 · The free tier, tested rather than assumed

7 · The claim path is built; the only thing missing is a subscription

Every platform asked the same question today — can you show control? Starbucks put it in one sentence: “a PoC file hosted on the affected domain confirming control.” A dangling CNAME proves a name is unused, not that it can be taken. So the claim itself is now machinery rather than advice: engine/azure_claim.py takes a name out of the book, re-checks with DNS that it is still unclaimed, creates the exact resource, and then proves the chain by asking the victim's hostname what it serves. Traffic Manager profiles cost nothing for a PoC (billing is per million DNS queries, and the endpoint points at a static page we already own).
