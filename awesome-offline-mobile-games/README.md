# Awesome Offline Mobile Games

Ten games that play with the radio off: four originals authored in this repo and six
cross-hybrids that cross one open-source title's systems with another's systems and art. No
accounts, no ads, no telemetry, no download-on-demand — once the folder is on your device,
nothing here ever opens a socket.

No slot is a clone. Every shipped title is code written here; the upstream projects appear as
pinned, attributed bytes under `vendor/`, never as a title of their own.

The rule this collection holds itself to: **no filler to hit ten.** Every slot has to clear
dozens of hours or a real skill ceiling. A slot that can't clear the bar stays empty.

### The six cross-hybrids

Each one takes a clone's *systems*, crosses them with a second clone's *systems and assets*, and
ships under its own name — the pairing is the point, so both halves are load-bearing:

| Title | Systems from | Crossed with | The mesh |
|---|---|---|---|
| **Siegehaus** | SPD's turn economy, permadeath, FOV, 6 sectors (via Vaultbreak) | Mindustry's production chain | Every turn is a production tick: drills mine seeded ore veins, belts carry tokens, fabricators press plates, turrets spend them. Walking and building compete for the same turn. |
| **Charterline** | Unciv's 74-tech tree, 31 units, 50 buildings, 23 nations (via Tessera) | Endless Sky's ten commodities + Luanti's node materials | Cities export one good cheap and import another dear, re-drifted each turn, so a route pays the live spread — not a flat road bonus. The map is textured in Luanti's grass/dirt/stone/sand/leaves/water. |
| **Nulltrace** | Rift Nine's nine grapple rooms and run structure | id's PM_Friction / PM_Accelerate / PM_AirAccelerate + DDNet's speedrun framing | Horizontal motion is Quake's, at the shipped constants (320/6/100/10/30), so speed is only bled by friction. DDNet contributes the unpausable run clock, splits, medal ladder and ghost. |
| **Lanternfall** | Endless Sky's 120-hull table, commodities, market (via Ember Drift) | Quake-era arena cadence | Ten-frag limit, two armour shards on 25 s and a weapon crate on 40 s, all on the HUD. Holding the timers wins the round; the credits they pay buy the next hull. |
| **Cinderhold** | Dungeon Crawl Stone Soup's vault corpus — 420 room layouts out of 6,127 hand-authored `MAP` grids, each with its depth band and tags | Flare's painted menu frames and 12 portraits for every window, plus 140 real item records | Every floor is cut from a DCSS vault instead of being generated by hand, so the level knows its own shape, depth and tags. Drops are Flare items with Flare's own level, price and damage numbers; only what you carry out survives. |
| **Wardenmarch** | Battle for Wesnoth's rule set — hit points, movement, cost, alignment and per-attack damage/number/range read out of 22 of its unit definitions | Dungeon Crawl Stone Soup's arena geometry | Units fight by upstream numbers, not invented ones, over battlefields cut from DCSS vaults. Terrain, sprites and portraits are Wesnoth's; the shape of the fight is DCSS's. |

The originals are not drawn from scratch: they run on real content taken out of those same
upstream projects — Endless Sky ship hulls and their sprites, Shattered Pixel Dungeon creature
sheets, dungeon terrain and sound effects, the actual Civ V technology tree from Unciv,
Cataclysm: DDA's item and recipe tables, SuperTuxKart's audio, Flare's painted monsters and item
records, Wesnoth's unit definitions and sprites, Dungeon Crawl's vault layouts and tiles —
578 files / 21.9 MB under `vendor/`, every one pinned to an upstream commit and verified by size
and SHA-256 on every test run. Downloading the art is not the claim being
tested: the harness hooks `drawImage` and fails the run if vendored sprites are fetched but
never painted.

Scores are this collection's own 1–10 judgement of depth and craft, not store ratings. The
scoring rubric lives in `docs/QUALITY-BAR.md`; the raw audit of the source repo is in
`docs/INVENTORY.md`.

## Play it

- live: **https://aomg-offline.pages.dev** (private repo, Cloudflare Pages; the custom
  domain `aomg.cluerholdings.com` is attached and waiting on one CNAME record)
- locally: `npm run build && npm run serve`, or open `dist/index.html` straight off disk

## Play it

```sh
git clone <this repo> awesome-offline-mobile-games
cd awesome-offline-mobile-games
npm run build && node tools/serve-dist.mjs   # http://127.0.0.1:8400 — serves dist/
python3 server/server.py                     # or: http://127.0.0.1:8787 from source
```

`tools/serve-dist.mjs` serves the built folder the way a host will: real MIME types, Range
requests for the `<audio>` in the hybrids, and `no-store` on `sw.js` so an installed worker can
update. That is what a tunnel or a static host proxies.

### A link for a phone, without deploying

```sh
node tools/serve-dist.mjs &                   # 127.0.0.1:8400
tailscale serve  --bg --https=8443 http://127.0.0.1:8400   # tailnet only
tailscale funnel --bg --https=8443 http://127.0.0.1:8400   # public, while it runs
```

`tailscale funnel status` prints the URL (`https://<machine>.<tailnet>.ts.net:8443`). Open it
once on the phone with Wi-Fi on, then *Share → Add to Home Screen*: the service worker has the
whole collection cached, so the icon plays in airplane mode. HTTPS also gives the PWA the
service-worker registration it needs — `file://` cannot.

Open the URL on your phone (same Wi-Fi) or in a desktop browser. On first load the service
worker precaches the launcher, all ten titles and the whole vendored payload (578
entries, 21.9 MB), so after that the phone can go into airplane mode and everything still opens
from the home-screen icon. Nothing in the collection is a clone of an upstream build: the grid
is four originals plus six cross-hybrids (SCOPE-GATE decisions 9 and 10), and every one of them is a
browser page. That claim is tested, not asserted:
`tests/offline.mjs` cuts the network at the DevTools protocol level, reloads, and requires the
launcher to still render all ten cards **and each title to boot, take
input and keep playing** (each one is checked for its own state advancing, with the vendored bundle confirmed
loaded from cache).

Two ways to play without any server at all:

- **file://** — open `shell/index.html` straight from disk. All ten browser titles are run from
  `file://` in `tests/browser.mjs` on every run, sprites and audio included, so this is a
  measured claim rather than a hope. The shell's service worker and the local-save API are
  unavailable there, so it falls back to `localStorage` only. Every game page is also runnable on
  its own, e.g. `games/vaultbreak/index.html`.
- **The port builds are not part of the grid** — `ports/<id>/PROVENANCE.md` remains as lineage
  paperwork (upstream repo, pinned commit, licence, artifact hash), which is not the same as
  shipping a clone. Nothing here needs an install step: every title is a bundled browser page.

## What's in the folder

```
catalog/games.json        single source of truth for the ten titles
shell/                    launcher PWA: index.html, app.js, styles.css, lib/gamekit.js
sw.js                     service worker at the ROOT — its scope must cover /games/
manifest.webmanifest      PWA manifest, scope "/" so the installed app owns the games
index.html                root redirect, for hosting the folder behind a static server
games/                    the ten browser titles, each a self-contained folder
  vaultbreak/             turn-based vault roguelike (canvas 2D)
  tessera/                hex 4X with one competent AI opponent
  ember-drift/            Newtonian space trading and combat
  rift-nine/              momentum platformer with grapple and ghost replays
vendor/                   real upstream content, converted: sprites, audio, game data
  MANIFEST.json           every vendored file: source path, commit, licence, size, sha256
  vendor.js               the bundle the games load (classic script, works from file://)
ports/                    six provenance manifests + build recipes (engines are not vendored)
  manifest.json           machine-readable: clone path, artifact path, licence
docs/                     SCOPE-GATE, INVENTORY, HYBRIDIZATION, QUALITY-BAR, VENDORED-CONTENT, LICENSING
tests/                    browser.mjs (headless CDP proof), smoke.mjs (static invariants),
                          vendor.mjs (upstream payload integrity), touch.mjs, offline.mjs, longrun.mjs
tools/                    vendor.py (imports + converts upstream content), sync-catalog.mjs,
                          ports-provenance.py, verification-report.py
server/server.py          localhost-only library server: static files, saves, catalog API
evidence/                 screenshots + machine-readable verification output (regenerated)
```

## Verify it yourself

```sh
node tools/sync-catalog.mjs --check     # catalog.data.js matches catalog/games.json
node tests/smoke.mjs                    # static invariants, no browser needed
node tests/vendor.mjs                   # vendored upstream payload: 578 files, size + sha256
node tests/browser.mjs                  # launches headless Chromium, plays each original
node tests/touch.mjs                    # dispatches real touch + key events at screen coords
node tests/offline.mjs                  # cuts the network at CDP level, reloads from cache
node tests/longrun.mjs                  # 200+ actions per original: late-game stability
python3 tools/ports-provenance.py --check
python3 tools/vendor.py --check         # same check, standalone
python3 tools/vendor.py sync            # rebuild vendor/ from the clones (needs the clones)
```

`tests/browser.mjs` is the one that matters: it loads each original at a 390×844 mobile
viewport, fails on any console error or exception, fails if the canvas is blank (fewer than 8
distinct colours), fails if the pixels do not change after input, calls the game's own
`window.__game.act()` surface to drive it, then re-runs **all ten browser titles** over `file://` to
prove they run with no server at all — and counts the `/vendor/` responses each page actually
fetched, so "it uses the cloned assets" is answered by the network stack rather than by a claim.
Screenshots land in `evidence/`. It exits non-zero on any failure, so CI can gate on it.

Every browser title also exposes `window.__game.state()` — the same surface the harness uses —
so you can poke at a running game from a devtools console.

## How the ten were chosen

Full reasoning in `docs/SCOPE-GATE.md` (what this is and is not) and `docs/HYBRIDIZATION.md`
(what was reused from where). Short version:

- The source repo's own scores put Mindustry, Shattered Pixel Dungeon, Luanti, Endless Sky and
  DarkPlaces at 9.0+; DDNet at 8.5. Those six became the port lane.
- The four originals exist because the source repo had no deep original mobile titles, only
  ports. Each one hybridises mechanics from two or more of the ports — Vaultbreak is SPD's turn
  economy crossed with Mindustry's scrap-to-craft loop; Tessera is Unciv's hex 4X economy with
  OpenTTD's road-trade logistics; Ember Drift is Endless Sky's flight model rebuilt as an
  arcade sandbox; Rift Nine takes SuperTuxKart's momentum feel and rebuilds it as a 2D
  speedrun platformer.
- The originals then got the real payload: ship hulls, sprites, audio and content tables are
  taken from those same upstream repos, converted to browser-loadable form, and vendored under
  `vendor/` with per-file provenance. `tools/vendor.py` does the conversion; `tests/vendor.mjs`
  fails the suite if any vendored file changes, goes missing, or stops being used by a game.
  Nothing is lifted from a commercial title: every donor here is an open-source project whose
  licence permits redistribution, and its licence text ships alongside its files.

## Shipping it

The repo is wired to the org's publishing pipeline (`RDW-Labz/ship-pipeline@v1`):

- `ship.config.yml` — project `awesome-offline-mobile-games`, build preset `web`, one target
  (`vercel`, preview deploy), `publish: true` (unpaused 2026-10-29).
- `.github/workflows/ship.yml` — calls the pipeline on a `v*` tag or by hand. A real publish
  needs **both** a `vX.Y.Z` tag and `publish: true`, so nothing goes live by accident.
- `.github/workflows/verify.yml` — the catalog check, the invariants and the byte-for-byte
  vendor check run on every push and PR.
- `npm run build` — the pre-publish gate: catalog in sync, 100 invariants, 84 vendored-payload
  invariants, then `tools/stage-dist.mjs` stages the runtime surface into `dist/` (400 files,
  6.6 MB) for the pipeline to deploy.

The Vercel secrets (`VERCEL_TOKEN`, `VERCEL_ORG_ID`, `VERCEL_PROJECT_ID`) are repo secrets pushed
from the vault with `scripts/sync-secrets.sh` in the pipeline repo — they are never committed here.

## TestFlight (iOS app) — parked

Parked 2026-10-29 while testing moves to the browser link (a Tailscale funnel URL, plus the
installed PWA which plays in airplane mode). The app builds and is proven in a simulator; it
waits on App Store Connect credentials. `.github/workflows/ios.yml` is now manual dispatch only,
so it does not spend macOS runner minutes on every push.

`ios/` wraps the same staged collection in a `WKWebView` shell that reads only from the app bundle,
so the installed app plays with the radio off. The Xcode project is generated from
`ios/project.yml` (XcodeGen), never committed:

```sh
npm run ios:payload     # build → copy dist/ into ios/web → verify it is byte-identical
```

- `.github/workflows/ios.yml` — a `payload` job that runs anywhere (no Xcode, no Apple account) and
  fails if the app would ship anything other than the tested collection, plus a `testflight` job on
  macOS that archives and uploads once the App Store Connect secrets exist. Without those secrets it
  stays green and reports the upload as skipped.
- `ios/README.md` — the secret list, the one-command Mac build, and the plane-mode test.
- Needs an Apple Developer account: `APPLE_TEAM_ID`, `APPLE_API_KEY_ID`, `APPLE_API_ISSUER`,
  `APPLE_API_KEY` (base64 `.p8`).

## Contributing a game

The bar is in `docs/SCOPE-GATE.md`. In short: it must run offline, be canvas-or-DOM only with
no dependencies, fit in one folder under `games/`, expose `window.__game.state()`/`act()` for
the harness, and pass `node tests/browser.mjs`. Then add a catalog entry and run
`node tools/sync-catalog.mjs`.
