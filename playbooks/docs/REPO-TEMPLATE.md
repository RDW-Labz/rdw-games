# T01 repository template

`template/common` supplies the shared layout and policies. `template/python`
adds Python 3.12, uv, pytest, Ruff, strict mypy, and an importable package.
`template/desktop` adds the Tauri 2 Rust shell and TypeScript/React frontend.
This is build scaffolding only; product behavior belongs to later tickets.

From this checkout, install the locked development environment:

```sh
uv sync --locked
uv run python -m garage.template --repo agent-core --target ../agent-core --check
uv run python -m garage.template --repo agent-core --target ../agent-core --write
```

Use any of the nine names in `src/garage/repositories.py`. Check mode exits 1
when managed files differ, 0 when they match, and never writes. Write mode updates
only paths supplied by the template. Review its diff before committing.
Repository-specific policies are rendered from that same registry.
The renderer requires this source checkout, including the `template` directory.

Changelog history and files outside the template are preserved. In particular,
existing design docs, connector catalogs, skill formats, person templates, and
application source outside the scaffold remain untouched. A symlink in an output
path is refused before writes begin. Use canonical paths (for example
`/private/tmp`, not the macOS `/tmp` symlink) for a target checkout. This tool does not create GitHub repos,
commit, push, merge, install dependencies, or run commands.

After rendering a Python checkout, run `uv lock`, commit `uv.lock`, and use the
README checks. Lockfiles are generated by package managers, never guessed by a
model. The desktop overlay contains its reviewed npm and Cargo locks; update
those with the package managers whenever dependencies change. Each repository
owns its changelog entry and pull request. Future changes to scaffold-owned
files need a reviewed template update before reapplying it.

CI runs on every pull request and push to main. Desktop checks compile the Rust
shell on Windows and macOS without creating signed installers. Signing,
auto-update, the orb, and service integration are later ticket work.
The remote repository has an import smoke test at T01; the 200-trace scrubber
suite is T04 and is not claimed by this scaffold.
